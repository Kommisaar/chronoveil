关系清单

1characters → character_instances 1 ─ N FK character_id（可空）：建会话选卡实例化的快照溯源；NULL = 动态造人（D6）。
2sessions → character_instances 1 ─ N FK session_id：会话阵容成员；用户扮演位 + LLM 位都挂这里。
3sessions → messages 1 ─ N FK session_id：会话消息流；updated_at 随新消息刷新（FR-007）。
4character_instances → messages 1 ─ N FK instance_id（可空）：说话人——user 消息 = 用户位实例，assistant = 生成位实例。
5sessions → scenes 1 ─ N FK session_id：场景线按 idx 单调自增，顺序即叙事顺序（FR-011）。
6scenes → messages 1 ─ N FK scene_id（可空）：插入恒 NULL，导演结算（commit_settlement）AttachRange 回填，唯一写入者。
7character_instances → character_state 1 ─ N FK instance_id NOT NULL：状态挂实例而非模板卡——会话隶属由实例携带（迁移 0009 换挂）。
8sessions → llm_calls 1 ─ N session_id（可空，FK）：每次 LLM HTTP 请求一条轨迹；现行写入方恒 Some。
9sessions → sessions（自引用） 1 ─ N 逻辑引用（无外键）：forked_from_session_id + fork_anchor_scene_idx——源会话软删不得阻断新时间线；锚记 scenes.idx 叙事位置，不记行 id。

约束与约定速查

全库软删除（ADR-009）：除 llm_calls 外每表带 deleted_at 墓碑；唯一约束一律只约束在世/生效行（partial unique index，软删后同键可重插）。
状态生效行判定：deleted_at IS NULL AND superseded_at IS NULL——墓碑是「清除」、superseded 是「演进取代」；同键 (instance_id, key) 演进为 append-only 历史链，时间线分叉靠 source_scene 做 as_of 还原。
D1「卡死人活」：实例的 name / persona / render_style 是建会话一次性快照，改卡不回写旧会话；例外——演出三参数（anim_*，0013）不快照，聊天流按卡现值实时读取。
D2 扮演位：全会话恰好 1 个 is_user = 1 实例，由应用层保证（数据库仅 CHECK 0/1）。
记账层与命名层：scenes 的 fic_day/fic_part 是时间唯一事实源（part 六值：清晨/上午/午后/黄昏/夜/深夜；day 线内单调不倒流），date_label 只是日历换算缓存。
wire 与存储两种形态：IPC 边界 camelCase DTO（tauri-specta 生成），落库 JSON 一律 Rust serde 产出的 snake_case（如 calendar_config、present），禁止混存直落。
llm_calls 日志旁路：无墓碑、只插不改不删；kind 的 CHECK 保留历史值 'draft'（历法起草已裁撤），Rust 枚举读到即判数据损坏。
迁移现状：0001→0014 单向追加；应用未发布无存量数据，schema 允许破坏性变更（发布后该豁免失效）。技术表 schema_version 由迁移器自用。
