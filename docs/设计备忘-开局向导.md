## 1. 定位与范围收窄

**一期做**：

1. **内置四预设历法**（现代公历 / 七曜和风 / 干支古典 / 架空「旧都历」）+「跟随角色卡」
   共五选项，常量数据内置，**零 LLM 依赖、离线可用、建会话同步完成**。概念文档
   「开局向导自动拟历（廉价结构化调用起草）」完整愿景留二期（§7-2）。
2. **起始锚设定**：起始「第 N 天 · 时段」（PARTS 六值，`fiction_time.rs:14`），落为首
   场景行的 `fic_day/fic_part`。
3. **首场景 seed**：建会话事务内直接写 `scenes` idx-0 行（location / time_note 可选），
   `present = [会话角色]`（对齐导演备忘 §7-7 v1 收窄）。
4. **会话日历显式覆盖写路径**：`sessions.calendar_config` 支持「向导显式指定 > 角色卡
   快照兜底」（现逻辑 `infra/storage/sessions.rs:31-40` 是无条件快照复制，需改造）。

**一期不做**：日历编辑器、角色卡上的日历编辑入口、多角色 roster、场景元信息 UI
（`list_scenes` 无 IPC，导演备忘 §5 二期项）、会话历法回写角色卡（违背 FR-013）、
引擎改动。

**引擎能力边界**：引擎只把 `---` 渲染为 `hr.scene` 场景线，无日期/场景头展示能力；
向导内不做 date_label 实时换算预览（避免与 `fiction_time.rs:90-131` 双写），只展示
预设的静态样例文本。

## 2. 数据形态

### 2.1 CalendarConfig：以合并后实现为准，预设 JSON 直接内置

**关键发现——概念文档与已合并实现存在 schema 偏差，预设必须按代码写**：

| 项 | 概念文档 §7.6 | 合并后实现 `fiction_time.rs:33-49` |
|---|---|---|
| festivals 键 | 「月名·日号」字符串 | **年内第几天整数**（`BTreeMap<i64, String>`，`:48`） |
| 其余字段 | name / months / days_per_month / day_names | 一致；serde 无 rename → **存储 JSON 键为 snake_case**（测试 `:171-177` 权威锁形） |
| date_label | 「白蜡月·晨露日」 | **含时段与节日括注**：`白蜡月·晨露日·夜（灯节）`（`:119-129`） |

`parse`（`:74-85`）缺键补默认、坏 JSON 降级默认历 + eprintln；`has_skin`（`:66-68`）
要求 `days_per_month > 0` 且月名/日名至少其一非空。约束：**每月天数固定**，预设统一
12 月 × 30 日 = 360 日一年，保证 day↔(月序, 日序) 双射（`:101-111`）。

### 2.2 起始锚的表达

**锚的居所 = `scenes` idx-0 行**，不新增 sessions 列、不做新迁移：

- `fic_day` = 起始日（默认 1，≥1）；`fic_part` = 六值之一（默认「夜」，§7-3）；
- `time_note` / `location` = 用户可选原文；`summary` = None；`present = [character_id]`；
- `date_label` = 落库前由 `fiction_time::date_label(&calendar, fic_day, fic_part)` 派生
  （与结算共用同一函数）。

否决「sessions 加 fic_day_anchor 列」案：锚的读方只有导演结算的 `latest_scene`
（`director.rs:478`），场景行就是自然载体。

### 2.3 session.calendar_config 写入路径（两案比较）

- **案 A（采纳）：扩展 `create_session` 参数**。`NewSession`（`models.rs:151-155`）增
  可选开局段；IPC `create_session`（`ipc.rs:387-395`）增 `opening: Option<SessionOpeningInput>`；
  存储层 `sessions::insert` 改单事务：「日历显式传入优先，否则角色卡快照兜底；开场
  场景行同事务经 `scenes::insert` 落库」。一次 IPC、一次事务、原子；既有调用方传
  `opening: null` 行为不变；whitelist 零新增。
- 案 B（否决）：新命令两步走，非原子、命令面与守卫复杂度全高。

## 3. UX 流程

现状：开新会话唯一入口是侧栏「+」对话框，点角色名即建（`Sidebar.tsx:499-529`）。
卡片「开新会话」入口已刻意移除（`CharactersView.tsx:10` 注释）。附带发现陈旧文案：
`zh.ts:28` `chat.empty` 仍写「从角色页开始新对话」，本切片顺手修正。

**推荐最小交互：新建会话对话框两段式升级**（仍在侧栏对话框内，选角色后进入开局
表单态）：

- ① 选择角色（点击后锁定，可返回重选）；

  旧都历），选中预设显示**静态样例行**（预设常量自带说明文本，如「霜月·晨露日 ·
  一年十二月，每月三十日；灯节（第45日）」）；开局「第 [1] 天 · 时段 [夜▾]」
  （六值下拉）；首场景 地点/时间原文 两个可选 Input；
- 「**直接开始**」= 降级路径：opening 全空提交（快照继承 + day=1 + part=默认），

## 5. 与结算链路的衔接

FR-014 无需改导演代码：

1. **首场景行直接 `insert_scene`**（create_session 同事务），不复用 `commit_settlement`
   （那是「边界快照 + 上场回写 + 消息归属 + 状态清算」语义，开场 seed 没有「上一场」
   与「状态」，套用只带一堆 None 支路）。
2. **锚的消费**：首轮结算 `gather_input` 读 `latest_scene` = 开场行 → prompt 上一场
   快照段显示开场行字段（无开场包时是退化分支）→ `normalize` 把模型 `fic_day` clamp
   到 `latest.fic_day`——**锚是账本单调的地板**。
3. **date_label 初始生成**：与结算 `build_write` 同一函数同一格式。
4. **边界快照模型下消息归属自洽**：开场段首次结算时作为「收束段」挂到开场行
   （`close_scene_id = 开场行 id`，summary 回写开场行）——开场行自然长成
   「header + 消息 + 摘要」。
5. **未配置导演模型时**：开局包照常落库，账本在、结算欠着（§7-2 欠账自愈一致）。
